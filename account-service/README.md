# Salam ID — GitHub 主存储、手动同步

实际入口：`https://lnzisnmpmtqfplncfugn.supabase.co/functions/v1/salam-id`（Supabase Free，新加坡）。

## 数据职责

- **GitHub 主存储**：小曲库保留原加密文件；增长后 `accounts/library/v1/<ID>.json` 自动成为加密索引，记录位于 `accounts/library/v2/<ID>/<prefix>.json` 自适应分片（目标约 240 KB 明文）。移除单账号 750 KB / 6000 条总量限制。每个分片独立 gzip + AES-256-GCM，AAD 绑定账号；索引与变更分片在同一次 Git 提交中发布。
- **Supabase**：只持久保存账号身份、不可逆密码校验、用户名索引、会话、注销状态、限流和订单配置缓存，以及少量账号备份任务状态。不会持久缓存曲库或待上传曲库。执行期间暂时解密、合并、加密音乐文件属于请求内存。
- **GitHub 账号备份**：原 `accounts/v1/<ID>.json` 和 directory 继续批量加密备份账号元数据，不含会话。旧版本的历史提交可能含当时加密的曲库快照；新提交不再复制曲库。
- Android 本地保留自己的曲库、同步游标和持久 outbox。账号数据与游客数据分离，本地音乐不上传。

## 请求模型

2026-11-22 网络更新：Android 账号请求复用带证书公钥校验的 HTTP/2 连接，并通过 `x-region: ap-southeast-1` 将本项目函数放在数据库所在的新加坡区域。系统 DNS 超过 150 ms 时与阿里公共 DoH 并行解析；建立连接失败且尚未发送 HTTP 头时，允许用加密解析结果换地址再连接一次。DNS 只收到服务器域名，不转发登录凭据或音乐。已发出的登录/修改请求不因网络异常自动重发。

`/v1/sync` 支持 gzip 上传及响应，保留旧客户端的普通 JSON；同时检查压缩包与解压后单批大小，拒绝损坏压缩内容。此为传输层压缩，不改变音乐文件加密与账号隔离。Android 账号 Card 显示本次操作已获云端确认的编辑数及进度条，跨批次/重连累计。未新增收费服务。

- 普通登录/改名/改密不下载曲库。首次开通会将游客音乐自动上传，失败保留待发队列；日常使用、启动和编辑不触发后台音乐同步。
- 上传请求同时受 500 条 / 约 320 KB 的批次预算控制；歌单定义先于曲目。上传只确认本机更改，不下载整库；独立记录每条已确认修订，避免上传后编辑仍拿旧下载游标当写入版本。
- 增量下载按索引的分片修订筛选，每次返回一个分片。续页固定到首个索引的 Git blob SHA，另一台设备中途写入不会让页码漂移。直到所有页获取成功才应用本机数据。
- 小文件无变化拉取通常 1 次 GitHub GET；小文件有改动为 1 GET + 1 PUT。分片库无变化拉取仍只读索引；写入读取索引与涉及分片，并通过约 6 次 Git API 请求原子提交；首次/增量分页下载按实际涉及分片数计费额度。不能继续用旧的“所有同步固定 2 次请求”估算。
- 相同 device/seq 重试幂等，失败保留 outbox。序列/游标漂移返回机器可读状态，客户端在当前操作内最多主动协调重试一次，不要求用户处理版本号。格式错误不再冒充版本错误。
- 账号元数据仍保存在 Supabase 与 GitHub 批量备份；音乐分片和索引仅存 GitHub。没有新增付费服务或自动收费配置。
- Github Contents 对大文件的读取限制通过 Git blob API 处理，不因为 JSON 变长就直接失败。GitHub/免费托管的配额和服务限制仍存在，不能承诺无限存储或无请求上限。

## 认证与管理

首次有效订单设置密码生成随机用户名和独立稳定 ID；支持两种密码登录、改名和改密。密码使用 32 字节随机盐、PBKDF2-HMAC-SHA256 600000 次、独立 PASSWORD_PEPPER 的账号绑定 HMAC。不存明文订单或密码。

Mac SalamCloud 新增 Salam ID 页面，分页读取账号，搜索用户名/ID/本机已知订单，查看会话数、注销及恢复。注销为**可恢复的账号停用**：即时拒绝后续登录/同步、清空会话，保留音乐数据及账号身份；不改订单列表，不把注销误用为订单退款/吊销。

管理 API 使用已有 Mac/服务端相同 GitHub 凭据生成 HMAC-SHA256，不把原始 GitHub token 发给管理 API。签名绑定版本、时间戳、随机 nonce、路由和 JSON 请求体；2 分钟有效，nonce 单次使用。管理权限仅现有仓库凭据持有人拥有，不向 Android 暴露。若两端更换成不同 token，管理授权会失败，应同步部署凭据。

`POST /admin/accounts` 分页最多 100 条，`after` 游标；`/admin/close`、`/admin/restore` 携带 id。返回不含密码校验或会话令牌。

## 部署与迁移

实际部署入口 `supabase/functions/salam-id/index.ts`；业务 `src/service.mjs`；GitHub Contents CAS 在 `src/github.mjs`。Free 及秘密配置保持原样，Mac 无须常驻。

升级后管理员调用 `/admin/migrate`，每次最多迁移 10 个旧账号。先确保音乐已写入 GitHub，再从工作数据库移除 records/devices。失败保留原数据；中断重试不覆盖已迁出的文件。首次旧账号手动同步也会完成同样迁移。禁止先清数据库再上传。

`node --test test/*.test.mjs` 覆盖主存储、失败保留、并发 CAS、幂等、迁移、管理鉴权与注销隔离。Android 和 Mac UI 的实际观感由用户验收，不执行设备操作。

## 多语言用户名更新（2026-11-22）

用户名/昵称继续共用显示与登录名称，长度仍为 3～24 个 Unicode 字符。支持中日文等 Unicode 文字、数字、横线 `-`、下划线 `_` 和合法组合附标；显示保留大小写（NFC），登录和唯一性索引使用 NFKC＋小写＋NFC。仅修改字母大小写也可保存显示变化，不改变 Salam ID。旧小写用户名索引无需迁移。拒绝空白、控制/不可见字符和保留键名。

已通过 5 项相关测试：字符集、大小写显示与登录、等价字符冲突、旧用户名兼容、备份恢复后的多语言登录。Android 仅更新规则说明，Mac 现有 Unicode 显示无需重新编译；不安装、不操作设备。

## 已注销账号删除（2026-11-22）

Mac Salam ID 列表对已注销账号同时显示“恢复账号”和“删除账号”。删除前明确确认 ID 与注销版本；正在使用的账号必须先注销。成功后立即从当前列表移除，不依赖再刷新才能隐藏。

`/admin/delete` 先持久提交删除意图并保持账号不可用，再将当前 GitHub 分支的账号备份替换为仅 ID/时间的加密删除标记，删除曲库文件、更新用户名索引，最后清除工作数据库账号和待备份记录。失败显示“删除中”，可以重试；恢复不能打断正在删除的账号。备份发布与删除共享串行保护并重验快照，避免旧备份写回。

订单清单不改动。订单仍有效时可重新开通，生成全新 Salam ID、密码与用户名，使用新的本地数据目录，不恢复旧曲库/设备序列。新旧身份映射随加密用户名目录备份。最小删除标记不出现在账号列表，不包含用户名、订单、密码或音乐。旧 Git 历史中的加密快照不重写，界面明确提示这一点。
