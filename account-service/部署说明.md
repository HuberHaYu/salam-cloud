## 密钥与数据库

Supabase 函数秘密配置：`AUTH_PEPPER`、`PASSWORD_PEPPER`、`ARCHIVE_KEY`、`CRON_SECRET`、`GITHUB_TOKEN` 以及非秘密运行选项。平台自动提供 `SUPABASE_DB_URL`，数据库密码没有进入 Android、仓库或交接文档。

本机部署密钥备份在 `/Users/a1234/.config/salam-id-deployment/runtime.env`，父目录权限 700，文件权限 600；它不在任何 Git 仓库中。不要把这个文件上传仓库、发聊天或当作普通日志展示。前三个核心秘密不可直接替换：会分别影响账号 ID/会话、密码验证和归档解密。`CRON_SECRET` 是独立的归档触发凭据，仅同步一份到 Supabase Vault 的 `salam_id_cron`；不要把密码 pepper 放进工作数据库。

工作状态位于私有 `salam_private` schema，表已开启 RLS 且未给匿名/普通登录用户策略，项目 Data API 已关闭。只有函数的数据库连接访问它。所有账号修改采用 PostgreSQL 事务与 advisory lock，跨函数实例也不会互相覆盖。GitHub 仍保存 gzip＋AES-256-GCM 加密检查点。

密码格式 `salam-password-v1`：32 字节随机盐，PBKDF2-HMAC-SHA256 **600,000 次**生成 32 字节，再以 PASSWORD_PEPPER 对版本、账号 ID、参数、盐和派生值做 HMAC-SHA256。只保存参数、盐和最终 tag，不存明文密码或中间派生值。已在真实免费函数中跑通，不降低工作因子。

## 认证和网络

订单首次开通设置密码并生成随机用户名，以后支持订单号＋密码或用户名＋密码。用户名唯一且可改，ID 不变；改密码需要当前密码，并吊销旧会话。普通同步只在服务端验证会话，不访问 GitHub 验证订单；订单清单在认证时使用，一小时缓存。

函数的 Supabase legacy JWT 检查关闭，因为这里使用 Salam 自己的订单/密码和会话认证；业务接口仍检查身份，归档内网接口检查独立 CRON_SECRET，数据库不对客户端开放。不要给客户端配置 service role key 或 GitHub token。

Android 保留既有国内 GitHub 镜像加速和签名验证。新加坡执行入口直连官方 GitHub，`GITHUB_PUBLIC_MIRRORS=false`，避免镜像缓存延迟影响新发布订单；源码中的公开镜像验签后备仍保留。登录凭据不进入公共镜像。

Android 使用正常证书信任/域名校验和 SPKI 公钥固定。当前配置包含叶证书及 Google Trust Services WE1 签发者 pin，同一签发者下正常续签不必关闭验证。更换签发链时，先通过签名配置发布新 pin，再切换证书。pins 是公开摘要，私钥不进入 App。

## 归档与恢复

`cron.job` 中 `salam-id-checkpoint` 每分钟检查是否有到期任务，仅到期时调用 `/internal/checkpoint`。空闲没有函数调用或 GitHub 提交。正常归档窗口十分钟，单批最多 20 账号，积压最快一分钟一批；写仓库前使用跨实例租约防止重复提交。

GitHub 路径为 `accounts/v1/<ID>.json` 和加密用户名目录。每批通常五次 REST 调用。并发发布时不强推；失败保留待归档状态并退避重试。GitHub 是延迟检查点，工作数据库应保留；只恢复归档会回退到上次检查点。加密全量历史仍会增长，后续按实际规模维护归档保留策略。

## 后续发布

源码入口：`supabase/functions/salam-id/index.ts`；私有工作表和 cron 定义在 `supabase/migrations/`。`src/postgres-storage.mjs` 是托管存储适配器；其他 `src/` 文件是业务实现，Node SQLite 入口仅作为可选本地适配，不在 Mac 常驻运行。
